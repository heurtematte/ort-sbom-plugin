# Development

## Building

The project is built with Gradle and requires Java 25, like ORT 98:

```shell
./gradlew build                 # compile and run the tests
./gradlew publishToMavenLocal   # publish the artifacts to the local Maven repository
```

The ORT version is set by the ORT version catalog in `settings.gradle.kts`. The plugin descriptor and the service
registration of the package manager are generated by the ORT plugin compiler (KSP) from the `@OrtPlugin` annotation.

## Project structure

```text
sbom-parser/
  src/main/kotlin/           format detection, parsers, format-independent model
  src/testFixtures/          SBOM fixtures, published as test fixtures of the artifact
  src/test/kotlin/           parser tests and the corpus test
sbom-sources/
  src/main/kotlin/           SBOM source files and the retrieval from Dependency-Track, sbomify, and URLs
  src/testFixtures/          a local HTTP server simulating these sources, for tests
  src/test/kotlin/           tests of the source files and the retrieval
sbom-package-manager/
  src/main/kotlin/           the SBOM package manager and the mapping to the ORT model
  src/test/kotlin/           tests with the ORT Analyzer and the corpus analysis test
ort-server/                  images of ORT Server with the plugin (Dockerfile, build script, Compose file)
docs/                        this documentation (Zensical)
```

## Tests

### Fixtures

The fixtures are real SBOMs from public sources, each with its expected format and specification version, so that the
tests cover the matrix of supported formats and versions:

- SBOMs of Eclipse Foundation projects from Maven Central, the GitHub dependency graph, and Eclipse Temurin;
- examples of the CycloneDX specification test suite (1.0 to 1.7);
- example documents of the SPDX tools (SPDX 2.2 and 2.3 in JSON, YAML, tag-value, and XML, also UTF-16 encoded);
- examples of the SPDX 3 model;
- outputs of Syft, including invalid metadata and Debian versions with an epoch;
- exports of sbomify (CycloneDX 1.7 and SPDX 3.0.1 written by another tool).

Their sources and licenses are listed in `sbom-parser/src/testFixtures/resources/sboms/SOURCES.md`. The fixtures are
published as the test fixtures of `sbom-parser`, so that applications using the plugin can use them in their tests.

### Corpus tests

Two further tests process every file of a corpus directory if the environment variable `SBOM_CORPUS_DIR` points to it:

- `SbomCorpusTest` parses all SBOMs. It fails if an SBOM is not detected or cannot be parsed, counts documents in
  deliberately unsupported formats separately, skips files that are not SBOMs, and prints the number of documents per
  format and specification version.
- `SbomCorpusAnalysisTest` runs the ORT Analyzer with the package manager on every SBOM and fails if ORT reports an
  error.

```shell
SBOM_CORPUS_DIR=/path/to/sboms ./gradlew test --tests '*Corpus*' --rerun-tasks -i
```

The reference corpus used during development consists of more than 760 SBOMs: the CycloneDX specification test suite
and examples, the SPDX specification, model, and tool examples, Syft outputs, the Kubernetes release SBOMs, the SBOMs
published on sbomify, and SBOMs of Eclipse projects. All of them are
parsed and analyzed without errors, except SPDX RDF/XML documents.

## Documentation

The documentation is built with [Zensical](https://zensical.org) and published to GitHub Pages by the `Documentation`
workflow on every push to `main`. To preview it locally:

```shell
pip install zensical
zensical serve
```
